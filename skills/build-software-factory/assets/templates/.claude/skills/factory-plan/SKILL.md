# Plan

<!-- phase-compact:v1 -->

1. Read the accepted brief, acceptance.md, tools.json, config.assumptions and task-plan.json. Follow the [Plan guide](../../../phase-plan-guide.md) for uncertainty, worker handoffs and task/evidence mapping before assigning work.
2. Define owned tasks, dependencies, allowed paths and shared budgets. Map applicable G1/G2 and post-action checks, preserving optional waivers. Before changing shared contracts, follow the guide's [impact tracing](../../../phase-plan-guide.md#trace-changed-shared-contracts); use its risk-fitted test-design and dashboard procedures when relevant. Plan missing tests at real project paths.
For enabled videos, map current triggers using the guide.
3. Exit with a dependency-valid plan, mapped criteria, feasible budgets and explicit approval points. Planning launches nothing; scoped evidence is distinct from whole-project readiness.
4. Return: status, input/output revision, artifacts, checks actually run, blockers and risks, next owner/action. A template, plan or config proves nothing ran.
