# Compact generated phase entrypoints

New factories have six short phase `SKILL.md` entrypoints: numbered inputs/work,
exit and return instructions, followed immediately by project research and shared
policy links. The minimal example fits within 300 words per phase, including
frontmatter, root preamble, research status and return contract. Selected project
practices remain complete and ordered; their content may legitimately exceed that
budget. Factory Run keeps its existing dedicated orchestration instructions.

The six `phase-<name>-guide.md` root contracts retain the complete detailed phase
procedures. Entrypoints require reading the applicable guide procedures before
acting. Guide paths are relative to the factory root. Shared policy and boundaries
still govern; record helpers do not enforce every prose requirement. G1/G2/G3,
applicable A/R and video checks retain their actual required/optional choices,
subject/target binding, failed history and truthful waiver reporting.

Disabled feature details are absent from the short entrypoints. Brief stable
conditional routes still refer to current configuration: read the relevant video
or continuous-intake guide procedures when those features apply. These routes
remain correct after a reviewed preference update, without frozen generated
enablement flags. CI guidance applies only to authorized CI-adoption work; there
is no invented CI-enabled setting. Detailed guides explain safe feature choices,
updates and boundaries; retaining guidance does not activate a feature.

## Existing factories: explicit reviewed migration

An installed update does not rewrite generated contracts. With the trusted builder
and approved interpreter, preview a separate local migration:

```text
python scripts/update_operations.py --factory <factory> --compact-phases
python scripts/update_operations.py --factory <factory> --compact-phases --apply --approve-plan <reviewed-digest>
```

Review the full diff first. This narrow mode recognizes only the exact current
detailed phase generation reconstructed from the retained guides and the captured
research, or the exact compact generation. It compares normalized contract hashes,
not arbitrary text similarity. Custom, older unsupported, missing, research-drifted
or addendum-modified phase skills are refused; do not strip custom instructions to
force acceptance. Existing custom phase guides are also refused. Required shared
support guides must already exist; missing support needs separate reviewed adoption.

The reviewed plan adds the six complete guides when absent, registers their hashes,
and replaces only recognized phase entrypoints. It preserves selected research,
living records, copied runtimes, provenance and unrelated custom contracts. Already
compact normalized-equivalent bytes are preserved for an idempotent no-op. Captured
research, recognized skills and referenced guides participate in concurrent-change
checks; the ordinary plan digest, backups, added-file inventory and manifest-last
apply order remain in force. An interrupted write is not a successful migration.

Run this separately from operations, assumptions, runtime or delivery migrations.
`--delivery-gates` still uses its existing full detailed addenda and does not depend
on newly generated guides, so it remains usable without compact adoption. A factory
whose skill contains such addenda needs a separately reviewed manual reconciliation
before compact adoption. No custom instruction is automatically extracted or merged.
